# OrangeHRM QA Portfolio

Independent QA assessment of OrangeHRM, covering manual testing, functional validation, risk-based testing, and test documentation.

## Project Overview

### What is OrangeHRM?

OrangeHRM is a web-based Human Resource Management System that helps organizations manage employee information and HR processes.

The system provides modules such as employee management, user administration, leave management and other HR related operations.

## Project Objective

The main objective is to evaluate the OrangeHRM features in order to identify potential defects and assess its software quality.

How can we do that? We can read the available documentation, analyze the product and, based on that information, create test cases, test executions and test plans. This allows us to perform functional testing and selected regression checks, during which potential issues can be detected and tracked. If an issue is verified as a defect, a report will be created containing a summary, description, steps to reproduce, actual and expected results, supporting attachments such as media files and logs, and a workaround if available.

Through this independent QA assessment, I aim to demonstrate my ability to identify potential issues, prioritize testing activities, analyze software behavior, and communicate findings clearly using professional QA practices.

## Testing Approach

This project will follow a risk-based testing approach, prioritizing OrangeHRM features based on their impact and the likelihood of failure. Rather than attempting to test every functionality, testing activities will focus on critical features and areas with the highest potential risk.

Test cases will be organized by module, functionality, and risk level to clearly identify core features and facilitate efficient test execution. This structure will allow critical OrangeHRM functionalities to be tested without wasting time searching through unrelated test cases. 

Functional, exploratory, and selected regression testing will be performed to validate expected system behavior and identify potential issues.

Based on my professional QA experience, I consider test case maintenance an essential part of an effective testing process. Throughout this assessment, test cases will be reviewed and updated when necessary to ensure they remain accurate, relevant, and aligned with the system's behavior. This will help maintain an organized and reusable test suite while avoiding unnecessary effort during future test executions.

Test execution results will be documented, including test status and supporting evidence when necessary. Any identified issues will be investigated to assess their impact, and confirmed defects will be recorded in detailed reports to ensure clear and consistent tracking.
